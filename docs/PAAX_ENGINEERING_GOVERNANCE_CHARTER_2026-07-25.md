# PAAX Engineering Governance Charter

## Authority classes

- **Observation:** native/OCR/vision/raw extraction; not engineering truth.
- **Candidate:** classified or measured proposal.
- **Verified:** `engine_verified` or `human_verified`, with evidence and project/revision scope.
- **Approved:** signed professional decision by an authorized role.
- **Superseded/Stale:** retained for audit but not operational.

## Action tiers

| Tier | Example | Authority |
|---|---|---|
| R0 | read/search/explain | automated, project-bound |
| R1 | draft RFI/report/measurement | automated, clearly labeled draft |
| R2 | reversible correction/grouping | reviewer approval according to role |
| R3 | publish quantity/RAB/schedule baseline | QS/Project Manager/discipline approver |
| R4 | safety/design/legal decision | licensed/authorized professional only |

Rules: no self-approval; source and formula version must be recorded; active conflicts block auto-confirm; standards/rates have edition/effective date; user correction is project-specific unless governance promotes it; AI never signs engineering deliverables.
