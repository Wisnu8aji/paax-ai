# Completion Report - Task R11 (Metering & Observabilitas)

## Ringkasan Eksekutif
Implementasi metering penggunaan AI (Token Counting) dan observabilitas untuk membatasi kuota token tenant, memastikan tagihan AI terukur, dan menyediakan kill-switch (fallback) ketika kuota habis atau dimatikan. Semua spesifikasi di R11 telah diimplementasikan dengan kepatuhan penuh terhadap **Aturan Emas PAAX**.

## Apa yang Diubah/Dibuat

1. **Skema Database Metering (`services/db`)**
   - Migrasi Alembic `0005_usage_metering.py` dibuat untuk tabel `tenant_quota` dan `ai_usage_log`.
   - Menambahkan model SQLAlchemy `TenantQuota` dan `AiUsageLog`.
   - Menambahkan endpoint:
     - `GET /usage/quota/check`: Cek sisa kuota tenant (create otomatis default jika belum ada).
     - `POST /usage/log`: Log penggunaan dan kurangi remaining quota.
     - `GET /usage/summary`: Summary dashboard pemakaian.
     - `GET /usage/anomalies`: Deteksi lonjakan anomali mingguan.

2. **Interseptor Usage (Client & Orchestrator)**

     - Ketika kuota habis, client otomatis downgrade menjadi `NullAiAssistClient` (rule-based fallback only, tidak error putus).
   - Di `ai-orchestrator`:
     - Menambahkan fungsi utility di `usage.ts`.
     - Memasang `checkQuota` pada endpoint sinkron `/chat` dan `/stream` sebelum pipeline berjalan, mengembalikan HTTP 429 jika kuota habis.

3. **Konfigurasi & Fallback**
   - Mendukung kill-switch melalui env `METERING_ENABLED=0` di service terkait untuk by-pass semua operasi (return 999999 quota, ignore logs).
   - Fallback graceful saat db-api error atau mati sehingga proses persepsi tidak terhenti oleh error DB usage.

4. **Automated Tests**
   - Dibuatkan `services/db/tests/test_usage.py` yang mendefinisikan pengujian untuk `check`, `log`, `summary`, dan `anomalies`.

## Keputusan Arsitektur
- **Sync vs Async Call di Document Intelligence**: Karena pipeline ekstraksi eksisting bersifat sinkron/thread-blocking, call log metering dibuat dengan "fire and forget" via event loop async FastAPI tanpa mengubah struktur pipeline eksisting (meminimalisir regression).
- **Rule-Based Fallback**: Degradasi anggun terpenuhi di mana saat kuota AI habis, sistem beralih penuh ke engine deterministik OCR/regex reguler.
